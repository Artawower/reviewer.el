#+TITLE: reviewer.el

reviewer.el is a minor mode for annotating a file, diff, or any Emacs
buffer without changing its content. Annotate a region or word, edit
the note in place, and render all of a buffer's annotations as a
plain org document -- file, line number(s), the quoted span, and the
note -- for your own reference or to hand off to an agent (for
example, [[https://github.com/xenodium/agent-shell][agent-shell]]) working on the same code.

https://github.com/user-attachments/assets/99aa946f-55a2-444f-8cae-292e24cfb378

* Usage

- ~reviewer-annotate~ :: Annotate the active region (or word at
  point), or edit the note on an existing annotation at point. A
  small =*reviewer-annotation*= buffer pops up to edit the note text:
  finish editing to save it (clearing the text deletes the annotation
  instead), or abort to cancel.
- ~reviewer-show-annotation-at-point~ :: Show the annotation at point
  in a posframe (author, time, note), until the next command. Falls
  back to the echo area if [[https://github.com/tumashu/posframe][posframe]] isn't installed.
- ~reviewer-delete-annotation-at-point~ :: Delete the annotation at
  point.
- ~reviewer-delete-region-annotations~ :: Delete all annotations
  overlapping the active region.
- ~reviewer-clear-annotations~ :: Delete all annotations in the
  current buffer.
- ~reviewer-render~ :: Render all annotations in the buffer as an org
  file in =/tmp/=, displayed in a =*reviewer:file*= buffer.
  ~reviewer-render-next-annotation~ and
  ~reviewer-render-previous-annotation~ move between entries there.
- ~reviewer-yank-render~ :: Render annotations and copy the result to
  the kill ring, without displaying the render buffer.
- ~reviewer-yank-render-file-name~ :: Render annotations to =/tmp/=
  and copy the render file's path to the kill ring.

All of the above are ordinary interactive commands: call them with
~M-x~, or bind them to whatever keys you prefer.

** Transient menu

reviewer-mode binds a default prefix key that opens a transient menu
(via [[https://github.com/magit/transient][transient]]) listing all of the commands above, grouped into
"review" (annotation commands) and "summarize" (render commands). Set
~reviewer-use-transient~ to ~nil~ to make that prefix a plain keymap
instead, dispatching straight to each command with no menu shown.

* Installation

** straight.el and use-package

#+BEGIN_SRC emacs-lisp
(use-package reviewer
  :straight (reviewer :type git :host github :repo "SreenivasVRao/reviewer.el")
  :hook (after-init . reviewer-global-mode))
#+END_SRC

~reviewer-global-mode~ turns on ~reviewer-mode~ in every buffer; hook
it to a single major mode instead if you'd rather opt in per-buffer.

For a local checkout instead of pulling from GitHub, use
~:local-repo~:

#+BEGIN_SRC emacs-lisp
(use-package reviewer
  :straight (reviewer :type git :local-repo "/path/to/reviewer.el")
  :hook (after-init . reviewer-global-mode))
#+END_SRC

** Doom Emacs

In =packages.el=:

#+BEGIN_SRC emacs-lisp
(package! reviewer
  :recipe (:host github :repo "SreenivasVRao/reviewer.el"))
#+END_SRC

In =config.el=:

#+BEGIN_SRC emacs-lisp
(use-package! reviewer
  :hook (after-init . reviewer-global-mode))
#+END_SRC

** Configuration

reviewer.el exposes these knobs, all under the ~reviewer~ customize
group:

- ~reviewer-highlight-face~ :: Face for the annotated region.
- ~reviewer-posframe-face~, ~reviewer-posframe-border-face~,
  ~reviewer-posframe-author-face~, ~reviewer-posframe-time-face~ ::
  Faces for the body, border, and header (author/time) of the
  posframe shown by ~reviewer-show-annotation-at-point~.
- ~reviewer-posframe-parameters~ :: A plist controlling the
  posframe's geometry: ~:border-width~, ~:fringe~ (the blank margin
  left and right, in pixels -- the same idea as a window's fringe),
  ~:width~ (fixed width in characters -- long notes wrap instead of
  widening the frame), and ~:min-height~ (lines).
- ~reviewer-use-transient~ :: Whether the default prefix key opens
  the transient menu (see above) or a plain keymap.
- ~reviewer-annotation-edit-buffer-action~ :: Where the note-editing
  buffer from ~reviewer-annotate~ pops up.

A full sample configuration, documenting each of these:

#+BEGIN_SRC emacs-lisp
(use-package reviewer
  :straight (reviewer :type git :host github :repo "SreenivasVRao/reviewer.el")
  :hook (after-init . reviewer-global-mode)
  :custom
  ;; Show a transient menu on the prefix key instead of a plain keymap.
  (reviewer-use-transient t)
  ;; Geometry of the posframe used to show an annotation at point.
  (reviewer-posframe-parameters '(:border-width 2 :fringe 16 :width 40 :min-height 5))
  :custom-face
  ;; Highlight for the annotated region itself.
  (reviewer-highlight-face ((t :inherit highlight)))
  ;; Posframe body, border, and header faces.
  (reviewer-posframe-face ((t :inherit tooltip)))
  (reviewer-posframe-border-face ((t :foreground "orange")))
  (reviewer-posframe-author-face ((t :inherit font-lock-keyword-face :weight bold)))
  (reviewer-posframe-time-face ((t :inherit font-lock-comment-face)))
  :init
  ;; Pop the note-editing buffer up below the current window.
  (setq reviewer-annotation-edit-buffer-action
        '((display-buffer-reuse-window display-buffer-below-selected)
          (window-height . 20))))
#+END_SRC

* Status

~reviewer-mode~ (create, edit, and show annotations) and the org
renderer are both in place. There's no persistence across sessions
yet.

* Comparison to related packages

** forge, lgtm.el, github-review, code-review

These packages all assume the thing under review is a pull request on
a forge (GitHub, GitLab, or Bitbucket) and that the endpoint is a
remote submission -- approving, rejecting, or commenting through API
calls, backed by OAuth tokens, diff-hunk anchoring, and server-side
threaded comments. reviewer.el isn't trying to solve that problem: it's
purely for commenting on buffers -- for your own reference, and to
guide an agent while it writes or edits code.

** [[https://github.com/bastibe/annotate.el][annotate.el]]

reviewer.el is similar in spirit to annotate.el: both are built around
a region- or word-triggered, in-place-editable annotation that leaves
the file's content untouched. annotate.el additionally persists
annotations to a database across sessions and supports reply threads;
reviewer.el adds a posframe for viewing an annotation at point and a
transient menu for discovering commands, neither of which annotate.el
has.
